Where assistance helps

1. Describe how you feel

Write a short sentence. Review suggested symptoms and explicit ratings, then choose which answers to use.

LOCAL DRAFTING ALREADY EXISTS · NO CLOUD AI REQUIRED
2. Add a medicine with less typing

Reading a label can fill the name, strength, and directions. Each field needs review. Unclear text stays unanswered.

LABEL READING EXISTS · PHOTO PROCESSING NEEDS CONNECTIVITY
3. Choose symptoms to track

Offer a short list, an explanation, and “Add your own.” Suggestions never become symptoms until the user confirms them.

CATALOG SUGGESTIONS + OPTIONAL AI ORDERING ALREADY EXIST
4. Explain progress and summary

Start with what changed, name the dates, and link to the supporting entries. Say when there is too little information.

FACTUAL EXPLANATIONS ALREADY RUN ON DEVICE

What changes in this direction

  • One filled action per section; secondary help is quieter.
  • Short labels and visible saved, draft, and empty states.
  • Less repeated text. Details open only when needed.
  • Results describe what was recorded, without claiming a medicine caused a change.

This is an interactive design proposal, not the installed mobile build. It uses sample data and makes no AI or health-data requests. More flexible AI wording would need an on-device model or separate permission to use a provider.
